03 — 프로젝트

프로젝트 2건

데이터 엔지니어링의 핵심인 수집·처리·저장·모델링·서빙·운영을 중심으로 정리했습니다.

핵심 성과

전수 벡터 검색의 지연·오검색 문제를 하이브리드 검색으로 개선했습니다. 프로젝트 기록 기준 검색 시간은 20초 → 15초, 정답률은 70% → 90%로 향상되었습니다.

구현 과정 전체 보기접기
1

GCS 데이터 레이크 및 BigQuery 적재

  • 공공 비즈니스 평가 API의 원천 JSON을 GCS에 아카이빙
  • MD5 해시 검증으로 데이터 전송 무결성을 확인
  • BigQuery에 biz_evaluations 및 ingest_metadata 구조로 적재해 데이터 계보를 관리
2

시맨틱 청킹 및 메타데이터 분리

  • 코드화된 원천 값을 임베딩 모델이 이해하기 쉬운 서술형 텍스트로 재구성
  • 지역·성별·연령대·업종명 등 정형 조건은 메타데이터로 분리
3

임베딩 및 ChromaDB 인덱싱

  • SentenceTransformers로 문장을 128차원 벡터로 변환
  • L2 정규화를 적용해 코사인 유사도 검색을 효율화
  • ChromaDB에 벡터·텍스트·메타데이터를 저장해 복합 검색을 지원
4

Gemini Query Planner

  • 자연어 질의를 JSON Schema 기반으로 구조화
  • Hard Filter와 Semantic Query를 분리해 검색 계획 생성
  • 예: “강릉 지역의 자동차 부품 판매업 여성 대표자” → 지역·성별·업종 조건과 의미 검색 문맥으로 분해
5

  • Streamlit에서 검색 계획·수동 필터·유사도 점수·사업자 상세 정보를 제공
  • FastAPI로 page_view, record_search 행동 로그를 비동기 수집
6

트러블슈팅 및 성과

전수 1:1 벡터 검색의 성능·정확도 문제

모든 벡터를 질의 벡터와 비교하면서 최대 20초의 지연이 발생했고, 지역·성별 등 정형 조건이 의미 유사도에 묻히는 오검색이 발생했습니다.

하이브리드 필터링으로 개선

Gemini가 정형 조건을 추출하고 ChromaDB where 절로 후보군을 먼저 줄인 후 벡터 검색을 수행했습니다. 기록된 테스트 기준 15초 / 정답률 90%로 개선되었습니다.

핵심 성과

ThreadPoolExecutor 병렬화로 크롤링 성능을 1.5배 개선하고, Canvas 그래프를 OpenCV로 수치화했습니다.

구현 과정 전체 보기접기
1

데이터 수집 및 병렬화

  • Selenium과 BeautifulSoup으로 맛집 상세 정보(메뉴·가격·영업시간·평점·리뷰)를 수집
  • 순차 처리의 I/O 병목을 해결하기 위해 ThreadPoolExecutor 기반 동시성 크롤러를 설계
  • 수집 처리 성능을 1.5배 개선
2

Canvas 데이터의 OpenCV 수치화

  • HTML 텍스트로 추출할 수 없는 방문자 요일·시간대별 Canvas 그래프를 캡처
  • Color Masking으로 그래프 픽셀 좌표를 추출해 혼잡도 지수로 변환
  • 비정형 시각 데이터를 추천 파이프라인의 정량 피처로 자산화
3

AWS Data Lake 및 DW 모델링

RawAPI·Crawling → S3
→
WarehouseRedshift
→
Transformdbt Data Mart
  • 원천 데이터를 S3에 보존
  • Redshift 적재 후 dbt 기반 분석용 Data Mart 구성
4

K-Means 클러스터링

  • 혼잡도·리뷰 감성·가격대·방문 목적 등 다차원 변수를 StandardScaler로 표준화
  • Elbow Method와 Silhouette Score를 비교해 k=8 도출
  • 군집별 테마를 매핑하고 추천 스코어링 알고리즘과 연계
5

Airflow 오케스트레이션 및 운영

  • API·크롤링 → CV 수치화 → S3 → Redshift → dbt를 Airflow DAG으로 표준화
  • Docker 환경으로 실행 환경을 일관되게 구성
  • 수집 건수·Null·결측치를 검증하고 Slack Webhook으로 장애 알림
6

트러블슈팅

중복 데이터 누적 문제

동적 렌더링과 페이징 과정에서 동일 Place ID가 반복 수집되는 문제를 확인했습니다. Place ID 기반 Set 중복 검사와 전처리 중복 제거·검증 로직을 추가해 데이터 정합성을 확보했습니다.

데이터 수집 속도 개선

초기 설계한 순차적 크롤링으로는 데이터 수집에 과도한 시간이 소요됨을 확인했습니다(200건 기준 8분 30초). 이를 Thread Pool 방식을 도입하여 병렬 크롤링 방식을 도입하여 기존 대비 수집 속도를 약 1.5배(8분 30초 → 5분 30초) 향상시켰습니다.
