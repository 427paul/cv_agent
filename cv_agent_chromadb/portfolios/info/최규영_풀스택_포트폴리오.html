03 — 프로젝트

프로젝트 3건

데이터 수집·처리·서빙부터 AI 활용 분석과 비즈니스 의사결정 지원까지, 문제 해결 과정을 중심으로 정리했습니다.

핵심 성과

전수 벡터 검색의 지연·오검색 문제를 하이브리드 검색으로 개선했습니다. 프로젝트 기록 기준 검색 시간은 20초 → 15초, 정답률은 70% → 90%로 향상되었습니다.

구현 과정 전체 보기접기
1

GCS 데이터 레이크 및 BigQuery 적재

  • 공공 비즈니스 평가 API의 원천 JSON을 GCS에 아카이빙
  • MD5 해시 검증으로 데이터 전송 무결성을 확인
  • BigQuery에 biz_evaluations 및 ingest_metadata 구조로 적재해 데이터 계보를 관리
2

시맨틱 청킹 및 메타데이터 분리

  • 코드화된 원천 값을 임베딩 모델이 이해하기 쉬운 서술형 텍스트로 재구성
  • 지역·성별·연령대·업종명 등 정형 조건은 메타데이터로 분리
3

임베딩 및 ChromaDB 인덱싱

  • SentenceTransformers로 문장을 128차원 벡터로 변환
  • L2 정규화를 적용해 코사인 유사도 검색을 효율화
  • ChromaDB에 벡터·텍스트·메타데이터를 저장해 복합 검색을 지원
4

Gemini Query Planner

  • 자연어 질의를 JSON Schema 기반으로 구조화
  • Hard Filter와 Semantic Query를 분리해 검색 계획 생성
  • 예: “강릉 지역의 자동차 부품 판매업 여성 대표자” → 지역·성별·업종 조건과 의미 검색 문맥으로 분해
5

  • Streamlit에서 검색 계획·수동 필터·유사도 점수·사업자 상세 정보를 제공
  • FastAPI로 page_view, record_search 행동 로그를 비동기 수집
6

트러블슈팅 및 성과

전수 1:1 벡터 검색의 성능·정확도 문제

모든 벡터를 질의 벡터와 비교하면서 최대 20초의 지연이 발생했고, 지역·성별 등 정형 조건이 의미 유사도에 묻히는 오검색이 발생했습니다.

하이브리드 필터링으로 개선

Gemini가 정형 조건을 추출하고 ChromaDB where 절로 후보군을 먼저 줄인 후 벡터 검색을 수행했습니다. 기록된 테스트 기준 15초 / 정답률 90%로 개선되었습니다.

핵심 기여

동적으로 로드되는 마켓컬리 상품 정보를 크롤링하고, 판매명에서 실제 제품명과 수량을 구분하는 전처리 흐름을 구성했습니다. 또한 공통 레이아웃과 대시보드·검색 기능을 구현해 여러 쇼핑몰의 상품 정보를 일관된 화면에서 탐색하도록 했습니다.

구현 과정 전체 보기접기
1

마켓컬리 상품 데이터 크롤링

마켓컬리 건강식품 카테고리의 상품 정보를 Selenium과 BeautifulSoup으로 수집했습니다.

  • 상품 정보가 초기 HTML에 모두 포함되지 않고 JavaScript로 동적 로드되는 구조를 확인
  • 카테고리 페이지에서 스크롤을 내려 상품이 로드되도록 한 뒤 HTML을 파싱
  • 수집 원천 데이터는 JSON으로 저장하고, 쇼핑몰별로 다른 데이터 형식을 통일할 수 있도록 필드를 정리
2

제품명·수량 전처리 및 데이터 적재

  • 쇼핑몰 판매명(display_name)에서 실제 제품명(product_name)과 수량(quantity)을 구분
  • 광고 문구·증정 행사·세트 구성 등으로 복잡해진 상품명을 정리하기 위해 LLM을 활용한 추출 프롬프트를 적용하고, 필요한 항목은 수작업으로 보정
  • 데이터에 고유 ID를 부여해 취합 과정에서 레코드가 섞이는 문제를 방지
  • Django 모델을 구성하고 전처리된 JSON 데이터를 SQLite 데이터베이스에 적재
3

공통 레이아웃 설계 및 대시보드 구현

문제: 팀원별 페이지의 디자인과 구조가 일관되지 않음

각 팀원이 담당 페이지를 별도로 구현하면서 화면 구성과 탐색 경험에 차이가 생겼습니다.

  • 공통 컨테이너와 네비게이션 바를 포함한 레이아웃 템플릿을 설계해 페이지 간 디자인 통일성을 확보
  • 전체 상품 수, 평균 가격, 브랜드 수, 카테고리 수 등 주요 통계량을 보여주는 대시보드 구현
  • 가격 분포, 인기 브랜드 Top 10, 카테고리별 상품 수를 시각화해 시장 현황을 한눈에 확인하도록 구성
4

상품 검색 및 데이터 탐색 기능

  • 상품명·브랜드명·쇼핑몰 정보를 기준으로 상품을 검색할 수 있도록 구현
  • 검색 결과 정렬과 페이지네이션을 적용해 상품 목록을 효율적으로 탐색하도록 구성
  • 검색 조건에 맞춰 상품 수, 평균 가격, 쇼핑몰별 상품 비율 등 관련 통계가 갱신되도록 구현
5

프로젝트 결과와 개선 과제

  • 4개 쇼핑몰의 상품 정보를 가격·브랜드·카테고리 기준으로 비교할 수 있는 웹 서비스를 팀원들과 완성
  • 기존에 정리해 둔 프롬프트와 코드 자산을 활용해 대시보드 및 총 5개 페이지를 짧은 기간 안에 구현
  • 향후 개선 과제로 주기적인 크롤링·적재 자동화, 상품명 및 구성 정보 추출 정확도 개선, 이미지 자체 저장·캐싱 필요성을 정리
담당 범위

마켓컬리 크롤링, 데이터 전처리, Django·SQLite 연동, 공통 레이아웃 템플릿, 대시보드와 상품 검색 기능을 담당했습니다. 랭킹 등 다른 페이지는 팀원별 담당 기능으로 구분했습니다.

핵심 인사이트

전체 평균에서 우수해 보였던 B 소재도 신규 타겟에서는 전환율이 낮게 나타나는 차이를 확인했습니다. B 소재 전면 확대 대신 리타겟팅·관심사 타겟에는 B, 신규 타겟에는 A를 유지하는 이원화 전략을 제안했습니다.

분석 과정 전체 보기접기
1

문제 정의: 클릭 성과가 예산 확대의 충분한 근거인가?

D2C 라이프스타일 브랜드의 Meta 광고 A/B 테스트에서 신규 소재 B가 CTR·Engagement 등 상단 지표에서 우수해 보였지만, 이 결과만으로 예산을 확대하면 실제 전환 성과를 놓칠 수 있다고 판단했습니다.

  • 분석 목적을 단순 소재 비교가 아닌 예산 확대 판단의 타당성 검증으로 정의
  • CTR과 Engagement 외에 CVR, CPA, ROAS를 함께 확인하도록 분석 기준을 설계
2

AI Instruction 설계: 분석 흐름과 검증 원칙 명시

01 Data Check데이터 구조·결측·범위 확인
→
02 Overall전체 퍼포먼스 비교
→
03 Segment타겟별 드릴다운
→
04 Funnel전환 단계별 병목
→
05–06인사이트·Action 제안
  • 6단계 분석 순서와 단계별 핵심 지표를 사전에 정의해 분석 누락을 줄임
  • 전체 평균만으로 결론 내리지 않기, 데이터에 없는 사실을 만들지 않기, 모든 결론에 근거 포함하기, 비즈니스 Action으로 연결하기를 Instruction에 명시
3

Gemini Antigravity와 Claude를 역할에 맞게 병행

  • Gemini Antigravity: VS Code 터미널에서 Agent 형태로 사용해 데이터 로딩, 세그먼트별 드릴다운, 퍼널 분석을 진행
  • Claude: 웹 프로젝트 기능에서 지침과 컨텍스트를 분리해 설정하고 HTML 대시보드 구현에 활용
  • Gemini가 생성한 대시보드가 기대에 미치지 못하자 시각화 구현을 Claude로 전환하되, 교체 전에 두 AI의 핵심 인사이트와 수치를 대조해 분석 결과가 일치함을 확인
분석과 시각화 결과를 분리해 검증

도구를 바꾸더라도 분석 결론을 그대로 신뢰하지 않고, 핵심 수치와 인사이트가 동일한지 확인한 뒤 시각화 결과물만 교체했습니다. AI의 출력 품질과 분석의 일관성을 별도로 점검한 과정입니다.

4

세그먼트·퍼널 분석으로 평균의 함정 확인

  • 전체 평균뿐 아니라 신규 타겟, 리타겟팅, 관심사 타겟으로 나누어 소재별 성과를 비교
  • 클릭 이후 전환 퍼널을 함께 살펴 상단 참여 지표와 실제 전환 성과가 다를 수 있음을 확인
  • 전체 평균에서 우수해 보이는 소재라도 타겟에 따라 전환 효율이 달라질 수 있다는 점을 데이터 근거와 함께 제시
5

HTML 대시보드와 실행 가능한 예산 운영안

  • 전체 성과, 타겟별 비교, 퍼널 분석을 HTML 대시보드로 구성해 마케팅팀이 결과를 직관적으로 확인할 수 있도록 정리
  • 리타겟팅·관심사 타겟에는 B 소재 집중, 신규 타겟에는 A 소재 유지라는 타겟별 소재 이원화 전략 제안
  • 후속 검증 과제로 B 소재 전용 랜딩페이지 A/B 테스트를 제안해 광고 소재와 랜딩페이지의 조합까지 확인하도록 설계
최종 제안

전체 평균만 보고 B 소재를 전면 확대하기보다, 타겟별 전환 성과를 기준으로 예산과 소재를 차등 운영하고 후속 실험으로 개선 효과를 검증합니다.
