04 — Implementation

핵심 구현 기능 상세

동적 수집 최적화, 비정형 이미지 자산화, ML 클러스터링 모델링 및 데이터 마트 파이프라인 전 과정입니다.

핵심 성과

비정형 Canvas 렌더링 그래프를 OpenCV 컬러 마스킹으로 전처리하여 데이터 자산화에 성공했습니다. 또한 ThreadPoolExecutor 병렬 처리를 도입해 수집 속도를 1.5배 개선하고, K-Means(k=8) 모델과 다면 스코어링 지표를 결합하여 추천 신뢰도를 극대화했습니다.

구현 과정 상세 보기접기
1

STAGE 01 · 대규모 맛집 데이터 수집 및 멀티스레드 병렬화

  • Selenium과 BeautifulSoup을 결합하여 카카오맵의 맛집 상세 정보(메뉴, 가격, 영업시간, 평점, 리뷰 등)를 정밀 파싱
  • 단일 스레드 순차 처리 시 발생하는 I/O 병목을 해결하기 위해 ThreadPoolExecutor 기반 동시성 크롤러 설계
  • 네트워크 지연 시간을 극복하여 전체 데이터 수집 처리 성능을 1.5배 대폭 향상
2

STAGE 02 · 비정형 Canvas 이미지의 수치화 (OpenCV Computer Vision)

  • HTML 텍스트로 조회 불가능한 '방문자 요일·시간대별 실시간 웨이팅/혼잡도' Canvas 렌더링 요소를 스크린샷으로 캡처
  • OpenCV 컬러 마스킹(Color Masking) 기법을 적용해 그래프 선 및 배경 격자를 필터링하고 픽셀 좌표(Y축)를 정량적 수치로 자동 변환
  • 텍스트 부재 데이터를 추천 파이프라인의 핵심 피처(시간대별 예상 대기 시간 지표)로 자산화 완료
비정형 데이터 자산화 핵심 원리

카카오맵의 실시간 방문 추이 그래프는 백엔드 API 대신 프론트엔드 Canvas 상에 드로잉되어 텍스트 추출이 불가능했습니다. 이를 해결하고자 특정 RGB 임계치를 지정한 컴퓨터 비전 마스킹 필터를 구축하여, 그래프 픽셀의 상대적 높이를 0~100 사이의 '혼잡도 지수'로 안정적으로 디지털화했습니다.

3

STAGE 03 · AWS S3 Data Lake 및 Amazon Redshift DW 모델링

  • 원천 수집 데이터는 AWS S3 버킷에 1차 적재
  • 분석 및 빠른 서빙을 위해 Amazon Redshift로 정규화 적재를 진행하고, dbt(data build tool)를 연동해 분석용 Data Mart 모델 구축
4

STAGE 04 · K-Means 클러스터링 & 추천 피처 엔지니어링

  • 혼잡도 지수, 리뷰 감성 점수, 가격대, 방문 목적 등 추출된 다차원 변수를 StandardScaler로 표준화
  • Elbow Method와 Silhouette Score를 복합 대조하여 데이터 분별력이 가장 우수한 최적 군집 수 k = 8 도출
  • 군집별 테마(가성비 맛집, 데이트 코스, 회식 전용, 웨이팅 핫플레이스 등) 매핑 및 추천 스코어링 알고리즘 연계
5

STAGE 05 · Apache Airflow 파이프라인 오케스트레이션

  • 크롤링 → CV 수치화 → S3 저장 → Redshift 배치 적재 → dbt 변환 → ML 추론 전 과정을 Airflow DAG으로 표준화
  • 모든 프로세스를 Docker 컨테이너 환경으로 격리하여 개발 및 운영 서버 간 일관성 보장
6

STAGE 06 · 데이터 무결성 검증 & Slack Webhook 모니터링

  • 각 단계별 수집 건수와 Null 값, 결측치 여부를 실시간 검증하는 데이터 품질 밸리데이션 로직 구성
  • Slack Webhook 연동을 통해 파이프라인 실행 상태, 처리 레코드 수, 장애 발생 시 실시간 Error Alert 전송 체계 구축
05 — Troubleshooting

트러블슈팅 및 문제 해결

데이터 수집 파이프라인과 Redshift 데이터 웨어하우스 설계 과정에서 직면한 병목을 로직 개선으로 해결했습니다.

문제 01 (실시간 데이터 부재) 식당 추천에 필요한 실시간 웨이팅·혼잡도 데이터 확보의 어려움
  • 현상 파악: 식당 추천의 주요 판단 기준인 실시간 웨이팅·혼잡도를 직접 나타내는 수치 데이터가 제공되지 않아 추천 피처로 활용하기 어려움
  • 해결 및 학습: 카카오맵에서 제공하는 요일·시간대별 방문자 데이터를 대체 지표로 활용해 시간대별 혼잡도를 추정하고, 추천 파이프라인에서 활용할 수 있는 피처로 구성
문제 02 (Canvas 데이터 추출) Canvas 그래프 형태로 제공되는 방문자 데이터의 직접 추출 불가
  • 현상 파악: 요일·시간대별 방문자 추이 데이터가 HTML 텍스트나 표가 아닌 Canvas 그래픽으로 렌더링되어, 일반적인 파싱 방식으로 원본 수치를 직접 추출할 수 없음
  • 해결 방안: OpenCV의 컬러 마스킹으로 그래프 영역과 선을 식별하고, 픽셀 좌표를 기준으로 그래프 값을 추출해 0~100 범위의 정량 지표로 변환하여 데이터 피처로 활용
문제 03 (수집 정합성) 초기 크롤링 시 발생한 중복 데이터 누적 및 이상치 발생
  • 현상 파악: 중복 데이터 수집으로 인해 초기 200건의 데이터가 가공 과정에서 1,600건 이상으로 누적되는 데이터 품질 결함 감지
  • 원인 분석: 카카오맵 API로부터 동일 식당 식별자(Place ID)가 반복 수집되는 문제 확인
  • 해결 방안: 수집 스크립트 단에 Place ID 기반 인메모리 Set 중복 검사 로직을 신설하고, 전처리 파이프라인에 중복 제거 쿼리 및 유효성 모니터링 경보를 보강하여 정합성 확보
문제 04 (데이터 수집 속도) 데이터 수집에 과도한 시간이 소요됨 (200건 기준 8분 30초)
  • 현상 파악: 초기 설계한 순차적 크롤링 방식으로는 네트워크 대기 시간 및 동적 페이지 로딩 속도로 인해 데이터 수집 효율이 낮음
  • 해결 및 학습: Python의 Thread Pool을 활용한 멀티 스레딩 방식을 도입하여 병렬 크롤링 방식 도입하여 기존 대비 수집 속도 약 1.5배(8분 30초 → 5분 30초) 향상
