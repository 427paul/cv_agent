02 — Data Pipeline

RAG 데이터 파이프라인 5단계

공공 원천 JSON 데이터가 검색 가능한 벡터 자산이 되어 대시보드에서 실시간 서비스되기까지의 엔드투엔드 흐름입니다.

Step 01 · Source JSON 원천 데이터 적재 공공 API 수집 원본을 GCS에 아카이빙하고 BigQuery에 배치 적재
→
Step 02 · Chunking 서술형 청킹 & 메타 분리 코드화된 값을 문맥 텍스트로 재구성하고 필터용 메타데이터 분리
→
Step 03 · Embedding 임베딩 파이프라인 구축 SentenceTransformers 기반 128차원 벡터 변환 및 L2 정규화 적용
→
Step 04 · VectorDB ChromaDB 적재 벡터·텍스트·메타데이터를 저장해 조건부 하이브리드 검색 인프라 완성
→
Step 05 · Serving 검색 대시보드 배포 FastAPI와 Streamlit 연동 및 사용자 검색 행동 로그 실시간 수집
03 — Architecture

시스템 아키텍처

데이터 수집(Data Ingestion), 하이브리드 검색 엔진(RAG Engine), 애플리케이션 서비스(Application)의 3-Tier 구성입니다.

01 · Ingestion Layer Data Lake / DW
공공 비즈니스 API
JSON 수집 및 무결성 검증, MD5 해시 검사 자동 수행
↓
GCS + BigQuery
Raw JSON 데이터 레이크 아카이빙, 분석 마트 및 실시간 감사 로그(Lineage) 확보
02 · RAG Engine Hybrid Search
Gemini LLM Query Planner
자연어 질의를 해석해 Hard Filter(정형)와 Semantic Query(비정형)로 의도 분리
↕ 하이브리드 필터링 (where + vector)
ChromaDB Vector Store
128차원 정규화 벡터 영구 저장, 성별·연령대·지역·업종명 메타데이터 사전 필터
03 · Application Serving & Log
Streamlit Dashboard UI
자연어 검색 인터페이스, 필터 수동 보정, 실시간 결과 카드 뷰어 제공
↓ HTTP Async Events
FastAPI Log Collector
page_view, record_search 등 사용자 행동 이벤트 실시간 구조화 로깅
04 — Implementation

핵심 구현 기능 상세

Cloud ETL부터 시맨틱 청킹, 하이브리드 검색 대시보드 연동까지 각 단계별 기술 구현 내용입니다.

핵심 성과

전수 비교 방식의 검색 지연을 하이브리드 필터링으로 25% 단축하고 검색 정확도를 70%에서 90%로 향상시켰습니다. 정형 조건 메타데이터로 후보군을 사전 압축한 후 벡터 유사도를 연산하는 구조를 설계해 오검색과 연산 부하를 모두 해소했습니다.

구현 과정 상세 보기접기
1

STAGE 01 · GCS 데이터 레이크 아카이빙

  • 공공 비즈니스 평가 API의 원천 JSON을 GCS(Google Cloud Storage) 버킷에 자동 업로드
  • hashlib 기반 MD5 해시 검증으로 네트워크 전송 중 데이터 유실 및 변조를 방지
  • Raw 데이터의 불변성을 유지하는 데이터 레이크 아카이빙 체계 구축
2

STAGE 02 · BigQuery 데이터 웨어하우스 모델링

  • 분석 및 확장에 용이한 정규 스키마(biz_evaluations)를 정의해 데이터 배치 적재
  • 적재 일시, 파일 크기, MD5 해시값, 실행자 정보를 기록하는 감사 메타데이터 테이블(ingest_metadata)을 운영해 데이터 계보(Lineage) 확보
3

STAGE 03 · 서술형 시맨틱 청킹 & 메타데이터 분리

  • 단순 키-값 형태의 코드화된 원천 값을 임베딩 모델과 LLM이 이해하기 쉬운 서술형 텍스트로 재구성
  • 검색 필터링에 사용할 핵심 조건(지역, 성별, 연령대, 업종명 등)은 구조화된 메타데이터로 분리 적재하여 이중 탐색 인프라 구성
4

STAGE 04 · 임베딩 & ChromaDB 벡터 인덱싱

  • 한국어 도메인에 특화된 SentenceTransformers 모델을 적용하여 문장을 128차원 벡터로 변환
  • 벡터에 L2 정규화를 적용하여 단순 내적 연산만으로 고속 코사인 유사도 도출 가능화
  • ChromaDB 영구 컬렉션에 적재해 빠른 벡터 유사도 검색과 복합 메타데이터 필터링(where 절)을 동시 지원
5

STAGE 05 · Gemini 기반 쿼리 플래너 (Query Planner)

  • "강릉 지역의 자동차 부품 판매업 여성 대표자"와 같은 비정형 자연어 질의를 프롬프트 엔지니어링과 JSON Schema로 분석
  • 정형 조건(Hard Filter): province, sex, bzc_nm 등으로 자동 추출
  • 비정형 맥락(Semantic Query): 의미 검색용 키워드 및 시맨틱 쿼리로 분리하여 정밀한 질의 계획 수립
쿼리 플래너 핵심 동작 방식

Gemini API가 자연어 질의를 수신하면 사전 정의된 JSON Schema에 따라 정형 조건과 의미 검색 텍스트를 구조화해 반환합니다. 이를 통해 오탈자나 모호한 자연어 표현 속에서도 DB 필터용 파라미터를 정확하게 매핑합니다.

6

STAGE 06 · 하이브리드 검색 & 대시보드 연동

  • 하이브리드 필터링: 메타데이터 조건(where)으로 검색 대상 후보군을 사전 압축한 후 잔여 데이터에 대해서만 벡터 유사도를 계산
  • Streamlit UI: 검색 계획 요약, 수동 필터 보정, 유사도 거리 스코어, 사업자 상세 카드를 직관적으로 제공
  • FastAPI 로깅: page_view, record_search 등 실시간 사용자 행동 로그를 비동기 HTTP 이벤트로 수집
05 — Troubleshooting & Impact

트러블슈팅 및 정량적 성과

전수 비교 방식의 벡터 검색이 야기한 지연 시간과 오검색 문제를 하이브리드 파이프라인으로 해결했습니다.

문제 정의 (Problem) 전수 1:1 벡터 검색 도입 시 발생한 성능 저하 및 정형 조건 왜곡
  • 지연 시간 발생: 수집된 모든 데이터 벡터와 사용자 질의 벡터 간 1:1 전수 내적 연산을 수행하면서 검색 완료까지 최대 20초가 소요되는 지연 발생
  • 정형 조건 왜곡: 고차원 벡터 공간에서 의미 유사도에만 의존하다 보니, 특정 지역이나 성별 같은 필수 정형 조건이 유사도 점수에 묻혀 잘못된 결과가 반환되는 오검색 발생 (정답률 70%)
해결 방안 (Solution) Gemini 쿼리 플래너 + ChromaDB Hard Filter를 결합한 하이브리드 파이프라인
  • 하이브리드 필터링 파이프라인 도입: 질의 수신 즉시 Gemini LLM 쿼리 플래너가 메타데이터 조건을 추출하여 ChromaDB where 절로 사전 전달
  • 후보군 사전 압축: 1차 필터링으로 좁혀진 대상군 안에서만 벡터 유사도 연산을 수행하도록 검색 순서를 개선하여 불필요한 계산량 제거
